# Quiet Element — 要素を非表示

Chrome Manifest V3 / バージョン 1.1.0 / 日本語UI / Chrome 120以上

AdBlockの「要素をブロック」に相当する**表示上の要素非表示ツール**です。ChappyBlockとは別の新規拡張です。通信を遮断する広告ブロッカーではありません。

**ライセンス：GPL-3.0-only。** [LICENSE](LICENSE) / [謝辞・出典](NOTICE.md)

AdBlockの公開実装から起動・選択・確認の流れを学び、MV3向けに独立実装しました。公開ソースを提供したAdblock, Inc.および貢献者に感謝します。AdBlockやChappyBlockの公式製品ではなく、提携・公認を示すものでもありません。

## ダウンロード

[GitHub Releases](https://github.com/sukesan666/quiet-element/releases) から配布ZIPを取得するか、GitHubの「Code → Download ZIP」でソース全体を取得してください。いずれも展開後の `extension` フォルダーをChromeへ読み込みます。

## 導入

1. ZIPを任意の場所に**すべて展開**します。
2. Chromeのアドレスバーに `chrome://extensions/` を入力します。
3. 右上の「デベロッパー モード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押します。
5. 展開したフォルダーの中の **`extension` フォルダー**を選択します。`manifest.json` が直接入っているフォルダーです。
6. Chromeの拡張機能メニューで「Quiet Element」を固定すると操作しやすくなります。

ZIPを直接Chromeにドラッグする方法では導入できません。読み込んだフォルダーは移動・削除しないでください。ソースの更新後は拡張機能ページの再読み込みボタンを押し、対象のWebページも再読み込みします。ビルドやNode.jsは導入時には不要です。

### 1.0.0から更新する場合

ルールを残すには、**前にChromeへ読み込んだ同じ `extension` フォルダー**内のファイルを1.1.0の本体ファイルで上書きし、拡張機能ページの「再読み込み」を押してください。その後、操作対象のWebページも再読み込みします。Chromeに表示されるバージョンが **1.1.0** になったことを確認してください。

新しい場所から別の拡張として読み込む場合は、前版のQuiet Elementを無効にし、新版だけを有効にします。この場合、以前のルールは自動移行しません。ChappyBlockのフォルダーを上書きしないでください。

## 要素を選んで非表示にする

1. 通常のHTTP/HTTPSページを開きます。
2. 拡張アイコン →「ページの要素を選ぶ」、またはページを右クリック →「Quiet Element：要素を選んで非表示」を選択します。
3. マウスを合わせた要素が緑色の枠で表示されます。対象をクリックすると**プレビュー**で非表示になります。リンク先へは移動せず、クリックだけでは保存しません。
4. セレクタとページの表示を確認し、「確定して保存」を押します。「選び直す」で対象を変えられます。
5. 「キャンセル」または **Esc** で保存せず元に戻します。保存エラー時もプレビューを戻します。

選択中はページ側のリンク、ボタン、主なポインター・キーボード操作を抑止します。スクロールして対象を探せます。Tab / Shift+Tabで確認パネルのボタンを移動できます。サイトが先に登録したイベントなど、すべてのページ動作の抑止を保証するものではありません。保存処理中は二重送信と取消の競合を防ぐためボタンを無効にします。

1.1.0ではAdBlockの公開ソースを調査し、依存スクリプトの順次読み込み → 明示的なUI起動 → 成功確認に変更しました。HTTPページでの初期化失敗と管理画面の通信エラーを修正しています。透明な入力オーバーレイでページを保護し、その背後の要素を座標から選びます。iframe上でクリックした場合は内部へ入らず外枠を選びます。詳しくは [AdBlockの処理トレースと対応表](docs/ADBLOCK-TRACE.md) を参照してください。

## 再訪問時の自動非表示

拡張メニューの「このサイトで自動適用を許可」を押し、Chromeのサイトアクセス確認を許可してください。**選択・保存は一時アクセスだけでも可能ですが、再訪問時の自動適用にはこの任意の許可が必要です。** 許可を拒否しても保存ルールは消えません。

許可する範囲は、その**正確なホスト名のHTTP/HTTPS**だけです。例：`www.example.com` を許可しても `example.com` や `news.example.com` は別扱いです。ルールは同じホストの全パス・全ポートで共有されます。Chromeのホスト権限ではポートを細かく限定できません。HTTP/HTTPSの両方の許可を要求するのは、同じホストで保存ルールを共有するためです。

保存されたルールがある、許可済みサイトだけに自動実行用のスクリプトを登録します。次回のページ読み込みと、動的に追加・変更された要素に適用します。初回ロードで一瞬見える場合があります。許可した直後は現在のタブにも読み込みますが、すでに開いている別のタブは再読み込みしてください。

Chrome側の「サイトへのアクセス」設定で許可を取り消したり「クリック時のみ」に変更した場合は、自動適用できなくなることがあります。拡張メニューで状態を確認してください。アクセス許可を解除しても、すでに実行中のタブのスクリプトをChromeが取り除くわけではありません。そのタブも停止したい場合はルールをオフにするかページを再読み込みします。

## ルール管理

- 拡張メニュー：現在のホストの一覧、セレクタ、位置依存の注意、個別オンオフ、個別削除、サイト単位の一時停止、拡張全体の一時停止。
- 「すべてのサイトのルールを管理」：全サイトの一覧と同じ管理操作。拡張機能ページの詳細 → 拡張機能のオプションからも開けます。
- 「サイトへのアクセス許可を解除」：保存ルールを残し、今後の自動アクセスを解除します。
- 「全件初期化する…」：確認ダイアログの承認後、全ルールと設定を削除して初期状態に戻し、任意のサイトアクセス許可も解除します。元に戻せません。

オンオフや削除は開いている対象タブにも通知します。全体またはサイトが停止中なら、新しく保存したルールも有効に戻すまで適用されません。削除した表示が戻らない場合、サイト自身や別の拡張が非表示にしていないか確認し、ページを再読み込みしてください。

## セレクタの安全策と限界

- 一意な安定IDを優先し、次にタグ＋クラス、親子パスを使います。長い数字列や生成された可能性の高いクラスを避けます。
- 必要な場合のみ `:nth-of-type()` を使い、確認画面・一覧で位置依存を明示します。安定性を保証できるセレクタが得られない要素は選べません。
- ページのルート、本文全体、main/header/footer/nav、主要ランドマーク、画面の幅90%以上かつ高さ80%以上のコンテナを保護します。
- 自動適用時も、セレクタが**ちょうど1要素に一致し、安全と判定された場合だけ**非表示にします。0件・複数件・構文エラーは非表示を見送ります。複数一致になった既存ルールは解除して表示を戻します。
- サイトのstyle属性を書き換えず、一時属性と専用CSSで非表示にするため、取消時に既存のインラインスタイルを破壊しません。
- 非表示CSSはChromeの `USER` オリジンで注入し、ページ側のインライン `display: … !important` にも優先させます。注入できない場合はページ内の専用スタイルにフォールバックします。
- 同じセレクタは重複保存しません。1サイト200件、全体1,000件、セレクタ長1,024文字までです。

サイトの改修や位置の変更で、別の1要素に一致する可能性は残ります。ページの意味まで判断する仕組みではありません。特に位置依存ルールは、表示が変わったらオフにして作り直してください。既に非表示の要素は寸法を取得できないため、その後のサイズ変更を完全には判定できません。複数のルールが親子に重なっている場合、一方だけを削除しても親のルールで隠れ続けることがあります。

## Chromeの制限・対象外

- `chrome://`、`chrome-extension://`、新しいタブ、Chrome Web Store（新旧URL）、その他Chromeが保護するページでは利用できません。PDF内蔵ビューアも対象外です。
- `file://`、`data:`、`about:` は対象外です。ファイルアクセス権限は要求しません。
- **iframe内部の要素は対象外**です。クロスオリジンiframe内部は同一オリジン制約や別のホスト権限が関係するため、迂回しません。本実装は同一オリジンiframe内部も選択せず、最上位ページだけで動作します。iframeの外枠を選べる場合は、iframe全体を非表示にできます。
- **Shadow DOM内部（open / closedとも）は対象外**です。closed Shadow DOM内部は通常のDOM APIでは参照できません。Shadowホスト自体を選べる場合は全体を非表示にできます。
- canvas/WebGLの内部、疑似要素、ブラウザー自身のUIは個別に選択できません。canvas要素全体を選ぶことはできます。
- ページの強力なCSS、独自のイベント、スクリプトによる要素の再構築や非表示属性の削除などで機能が競合することがあります。
- 要素を表示上で隠す機能です。画像・広告・トラッカーの通信、動画や音声の再生、ページスクリプトの実行は止めません。
- 通常のChromeデスクトップを想定します。シークレットモードは既定でオフです。有効にした場合、ルールを通常モードと共有するため別の保存領域にはなりません。

## 権限・保存データ

| 権限 | 用途 |
|---|---|
| `activeTab` | ユーザーが操作したタブで選択UIを起動する一時アクセス |
| `scripting` | 選択UIの注入と、許可済みサイトの自動実行登録 |
| `storage` | ホスト名、CSSセレクタ、オンオフ、作成日時、内部IDを端末の `storage.local` に保存 |
| `contextMenus` | 右クリックから選択を開始 |
| 任意のHTTP/HTTPSホストアクセス | 明示して許可したホストに限り、再訪問時に自動適用 |

インストール時に全サイトへの必須アクセスを要求しません。`optional_host_permissions` の広い宣言は、後からユーザーが選んだ個別ホストを要求できるようにするためのものです。全ホストへの許可を一括要求する処理はありません。

Cookie、履歴、ダウンロード、クリップボード、通信監視の権限は使いません。外部サーバー、解析、テレメトリー、リモートコード、クラウド同期はありません。セレクタに使うIDやクラスにサイト固有の識別子が入る可能性はあります。拡張のアンインストールでChrome側の拡張データが削除されます。

## 同梱物・開発・検証

- `extension/`：そのままChromeで読み込める本体。実行時の追加依存なし。
- `tests/`：保存モデル、service worker境界、実ブラウザーDOM/UIの自動テスト。
- `tools/check.cjs`：Manifest・権限・参照ファイル・構文検証。
- `tools/build.ps1`：配布ZIPの作成。
- `docs/TEST-REPORT.md`：実行結果、未確認項目、手動確認手順。
- `docs/DESIGN.md`：設計・作業記録。
- `docs/ADBLOCK-TRACE.md`：AdBlockの参照ファイル・関数、対応する今回の実装、前版の不具合原因。
- `CHANGELOG.md`：新規作成ファイルと変更内容。

開発用テストはNode.js 22以上とPlaywrightが必要です。本体のインストールに開発依存は不要です。

```powershell
npm install
npx playwright install chromium
npm test
npm run test:native
npm run check
powershell -ExecutionPolicy Bypass -File tools/build.ps1
```

既存Chromeをテストに使う場合は `CHROME_PATH` に実行ファイルのフルパスを設定できます。`PLAYWRIGHT_PATH` で既存のPlaywrightパッケージを指定することもできます。

`npm test` はモデル・DOM・UI・ネイティブ拡張テストをすべて実行します。`npm run test:native` はネイティブ拡張テストのみ、`npm run test:dom` は境界アダプターを使う従来のテストのみです。

ネイティブテストは専用の一時プロファイルに拡張を実際にインストールし、Chrome DevTools Protocolの `Extensions.loadUnpacked` / `Extensions.triggerAction` で本物の拡張メニューを操作します。普段使うChromeプロファイルは変更しません。検証に使用したのはChrome **155.0.8059.40** です。ブラウザーがこれらのテスト用APIに未対応の場合は新しいテスト用ブラウザーを使ってください。`--enable-unsafe-extension-debugging` はテスト専用プロセスだけに付け、本体や通常利用には不要です。

HTTP・HTTPSの起動テストには**配布本体そのままのManifest**を使用します。再訪問の自動適用テストだけは、ネイティブ許可ダイアログを無人操作しないため、一時コピーへテストサイトのHTTP/HTTPS必須ホスト許可を追加します。配布本体の権限を広げるものではありません。実機検証結果と手動確認が必要な項目は [検証レポート](docs/TEST-REPORT.md) を参照してください。
